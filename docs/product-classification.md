# 商品の分類（#529）

日本語サイト（`/ja`）で、体験をカテゴリーなどから探せるようにするための商品の項目。2026-11-14 のオーナー指示（完成版を目指す。親は #561）。

## 項目（`packages/experience-domain/src/classification.ts` が正本）

- **カテゴリー（1つ）**：歩く／つくる・食べる／手を動かす／禅と寺／朝と夜／海／人に会う／団体・チームで
- **エリア（1つ）**：鎌倉駅まわり／北鎌倉／長谷・由比ヶ浜／材木座／二階堂・十二所／腰越／大船・山のほう／逗子／葉山
- **だれと（複数可）**：ひとりで／ふたりで／友人と／子どもと
- **こんな日に（複数可）**：雨の日に／特別な日に（「だれと」とは別の条件）

どれも空でよい。決めていない商品は、日本語の一覧の「すべて」にだけ出る。キー（`walk`・`kita` など）がDB・URLの値で、表示名は定義から引く。定義にない値はDBのCHECKとAPIで拒否する。

## 保存と反映

- 表 `experience_product_classifications`（migration `0075`）。商品ごとに1行（`(provider_id, product_id)`）。公開版（publication）の一部ではなく、変えると日本語の一覧・カード・詳細に**すぐ**反映する（再公開は要らない）。公開側が読むのは公開中の商品の行だけ（`ProductClassificationRepository.listPublic`）で、下書き・停止中・保管の分類は出ない。
- **だれが変えるか**：その商品の提供者の OWNER（ホスト画面の体験の編集の上の「日本語サイトでの分類」。`/host/api/products/{id}/classification`）と、NIHO事務局。共同ホスト・編集者・閲覧者は変えられない。
- **事務局のまとめ入力**：Admin › 提供者 › 「商品の分類」（`/admin/products/classification`）。商品を並べて個別に選ぶほか、行を選んでカテゴリー・エリアを一度に入れられる（全部成功か全部失敗）。代理登録した商品の編集画面にも同じ欄がある（`/admin/api/product-classifications`）。
- runtime role は INSERT・UPDATE のみ（`scripts/gcp/experience-db-grants.mjs`）。

## 検索公開の方針（#529 の受入）

カテゴリーの一覧（`/ja/experiences?category=…`）は、その分類の商品が1件以上あるときだけ検索に出す。絞り込みの組み合わせ（エリア・だれと・こんな日に・人数・日にち）のURLは `noindex, follow` とし、薄い一覧を無制限に作らない。空のカテゴリーは一覧の見出しを出さず「すべて」と相談の入口を出す。詳細は `/ja` の一覧の実装（別PR）に従う。
