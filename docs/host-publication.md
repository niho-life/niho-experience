# ホスト自身による体験の公開

オーナー決定: 2026-11-03。[#369](https://github.com/niho-life/niho-experience/issues/369)。本書は提供者の事前審査・体験ごとの掲載承認を廃止する方針の正本とする。体験業務の所有先は [ADR 0002](adr/0002-experience-domain-ownership.md) に従う。

## 公開の方針

体験の販売主体はホストとし、NIHO は公開・予約・決済連携を提供する。必要な情報と口座の準備が整った OWNER は、掲載条件に同意して自分で公開する。通常の原稿修正で掲載を止めたり、事務局の承認を待ったりしない。

Stripe の本人確認・口座の利用可否は公開と販売の条件として残す。NIHO 独自の掲載審査とは分ける。Direct charges だけを根拠にプラットフォームの責任や不正対応がなくなるとは扱わず、口座構成と責任分担は既存の限定契約を維持する。

| 状態 | ホストの操作 | 結果 |
| --- | --- | --- |
| 下書き | 必要条件を満たして「同意して公開」 | 公開中。審査待ちを挟まない |
| 公開中 | 原稿・写真・開催条件を保存 | 公開条件を満たした版を反映し、公開を維持する |
| 公開中 | 「掲載を止める」 | 停止中。新規受付を止め、既存予約は保持する |
| 本人が停止中 | 必要条件を満たして公開を再開 | 公開中。初回公開日を維持する |
| 運営が停止中 | 理由と問い合わせ先を確認 | 本人の再開では解除しない。運営の解除後に本人が再開できる |

運営停止は本人の停止と独立して保持し、既存の `PAUSED` から理由を推測して本人による解除を許可しない。旧審査待ちの体験を、移行時に自動公開しない。OWNER が必要条件と公開内容を確認して公開する。

## 公開・保存の条件

公開・再開時はサーバーが、現在の OWNER 権限、アカウントの利用可否、販売者と接続口座の一致と readiness、最新の掲載同意を確認する。原稿・写真の公開許諾、販売者表示、料金・定員・日程・取消条件などの必要情報が不足しているときは、直す項目と設定への入口を示す。提供者の `APPROVED` や事務局の掲載承認を条件にしない。

同意の版はサーバーが返した値を保存し、古い版・別提供者・非OWNER・運営停止の解除を試みた操作を拒否する。未保存の入力を公開しない。保存・公開の競合は版で検出し、通信断で結果が不明なときは同じ命令の照合または最新状態の再読取りを行い、成功を推測しない。

公開中の通常保存は事務局の再確認に戻さない。公開条件を満たさない変更を拒否するか下書きとして保持し、以前の公開版を保つ。日本語原稿から未確定の英語を作っただけでは公開版を更新しない。編集途中の必須項目不足を理由に、保存済みの公開版を消さない。口座・権限の失効や運営停止は、通常編集とは別に新規受付を止める。

価格・販売者・手数料・取消条件・予約者が同意した内容は予約時点の snapshot を保持する。原稿修正・公開停止・公開再開で既存予約の条件、席、返金記録を変更しない。運営停止中も、権限のある人が既存予約を照会・履行・取消／返金できる経路を残す。

## 現行 API からの移行

**実 API は移行前であり、この方針の仕様合意を稼働済みと扱わない。**

| 経路 | 状態・正本 | 扱い |
| --- | --- | --- |
| `/host` の画面モック | このリポの合成データと画面内状態 | 新しい公開・停止・再開を確認する。実保存・販売・メール送信の証跡にはしない |
| 現在の HTTP 版の編集・掲載 | NIHO Host API 0.4.0（選別契約・draft）。提供者と掲載に審査があり、保存で掲載が止まる | 実際の状態を表示し、保存時停止の説明を維持する。申請の API を「即時公開」と表示しない |
| 移行後の編集・公開・SSR | experience API v1 と体験専用 DB。公開の契約・永続化は #369 の残作業 | 公開版と編集内容、本人停止と運営停止を明示し、必要条件だけで自己公開する |
| NIHO 共通アカウント・Connect | NIHO の本人・権限・口座の限定契約 | 現在の状態をサーバー間で確認する。体験審査を新設しない |

旧契約の生成型や mock を、新しいサーバー仕様に配備済みであるように書き換えない。NIHO 側に新たな体験掲載機能を増やさず、[#330](https://github.com/niho-life/niho-experience/issues/330) の移行に、experience 所有の原稿編集、公開状態の永続化、公開カタログ・詳細・SSR/SEO の読取り切替を含める。商品ごとの販売切替と本文の公開停止を混同せず、同じ開催回を新旧双方で販売しない。

## HTTP 切替の受入

- OWNER の公開→原稿修正・保存して掲載維持→本人停止→本人再開を、再読込み後も同じ状態で確認する。
- 未保存・掲載同意不足／旧版・口座未準備・販売者情報不足・未確定翻訳・別提供者・非OWNER・権限失効・競合・通信断で誤公開しない。
- 運営停止をホストの再開や原稿保存で解除できない。停止理由のうちホストへ渡せる情報だけを返す。
- 公開・更新・停止をカタログ、詳細 SSR、metadata、sitemap、新規 checkout に反映し、停止後の公開 cache から非公開情報が漏れないことを確認する。
- 価格等の編集後も既存予約の snapshot と取消／返金の処理が変わらないこと、新旧で同じ開催回を販売しないことを確認する。
- 合成データの対象テスト、固定 SHA の staging 受入、権限・口座の限定契約の配備を確認してから HTTP 版を切り替える。これが終わるまで #369 を close しない。
