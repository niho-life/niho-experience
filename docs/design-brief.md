# デザイン方針

## 目指す印象

シンプル、スタイリッシュ、直感的。朗らかで親しみやすく、初めての土地でも安心して人に会いに行ける。
参考は [Slowhop](https://slowhop.com/en)。2026-10-19に英語トップと掲載カードを確認した。

v1からこの方向で作る。体験を比較して予約できる機能を備え、v3で読み物や地域案内が増えても同じ世界観を続ける。

## 採り入れる要素

- 大きな写真で人・手仕事・食卓・土地の空気が伝わる。
- 明るい背景、ゆとりのある余白、読みやすい文字、控えめな区切り線。
- シンプルなヘッダーと検索。主なCTAが一目で分かる。
- 提供者の顔・名前・話を商品の価値として見せる。
- 整理された写真カードと、親しみやすい短いコピー。

NIHO独自の色・文字・レイアウトへ翻訳する。Slowhopの写真、ロゴ、文章、ページ構成をそのまま複製しない。画像は使用許諾のある素材か明示した仮素材を使う。
2026-10-20の刷新で、白基調のニュートラルな地に、手描きのアイコン・手書きのアクセント・切手の縁と丸スタンプを加えた（[design-system.md](design-system.md)）。

## v1の主要画面

2026-10-27 のホスト設計更新: [ADR 0002](adr/0002-experience-domain-ownership.md)。提供者は `/host/calendar` で体験ごとの繰り返し開催枠（毎日・毎週・土日・曜日指定）と個別の休止・変更を管理する。Google の予定は同じ時間軸に「予定あり」として表示し、件名や参加者は体験サイトへ出さない。連携が切れ、空き判定が古いときは受付停止と再接続の理由を提供者に明示する。確定予約は専用カレンダーへの書き込みを選べる。旅行者向け UI は英語先行、ホスト管理 UI は日本語で設計する。

2026-10-30 のカレンダーUI: PC は7日×時刻の週表示、携帯は7日の選択と当日の予定にする。主操作は「枠を追加」、単発を既定にし、追加・回の変更は native dialog に閉じ込める。表示時間は9〜20時を基本にし、実データに早朝・夜間・日跨ぎの予定があれば切らずに広げる。重なる枠は同じ時間軸で横に分ける。内部 availability reason は見せず、「受付中」「休止」「満席」「締切」「予定あり」「確認待ち」と予約有無だけを示す。回の詳細は日時と状態を先にし、掲載先は折りたたむ。保存の受領と外部反映は分け、外部状態は `SYNCED` のときだけ「反映済み」、`PENDING` / `UNVERIFIED` / `ERROR` と読込失敗はそれぞれ「反映待ち」/「未確認」/「要確認」とする。DTOにない会場・講師・予約単位は補わない。

| 画面 | 最初に伝えること | 主な操作 |
| --- | --- | --- |
| トップ・一覧 | 鎌倉の人とどんな時間を過ごせるか | 体験を見る、日程・テーマで絞る |
| 詳細 | 誰と何をするか、内容・言語・所要時間・料金・集合概要 | 日時と人数を選ぶ |
| 予約入力 | 選択内容、合計、販売者、取消条件、必要な連絡先 | 決済へ進む |
| 決済からの復帰 | 予約状態と次に取る行動 | NIHOの予約確認へ、体験探しに戻る |
| 提供者入口 | 登録後の流れとNIHOが手伝うこと | NIHOでログインして始める（ログイン後はこのサイトのホストの画面へ） |

最初の商品数は3〜5件を目安にする。少数でも魅力が伝わるレイアウトにし、空のカテゴリや結果0件ばかりの検索を主役にしない。掲載のない機能を動いているように見せない。

## 確認条件

- 360pxのモバイルとデスクトップで一覧→詳細→予約の流れを確認する。320pxでも主操作が横にはみ出さない。
- 金額は円、開催日時は現地のJSTと分かる。料金の単位、総額と追加料金、言語、人数条件、キャンセル条件を予約前に確認できる。
- キーボード操作、focus、ラベル、コントラスト、画像代替文を確認する。大きな写真でも重要本文と操作が読み込める。
- 読込中、空、満席、販売停止、通信失敗、期限切れ、決済取消をデザインする。
- レビューや人気表示は実データがある場合のみ。架空fixtureはプレビューに限り、実績と誤認させない。
- v3の読み物は同じカード・文字・余白の設計で追加できる。v1の段階で大量の記事を埋めることを前提にしない。
