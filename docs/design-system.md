# デザインシステムと画面仕様（v1）

[#6](https://github.com/niho-life/niho-experience/issues/6) の成果物。方針は [design-brief.md](design-brief.md)。実装は `apps/web/src/app/globals.css`（token）と `apps/web/src/components/`。
画面はプレビュー（mock）で確認できる：`npm run dev` → `/`、`/experiences`、各体験、`/host`、`/preview/states`。`MOCK_CATALOG=pilot` で掲載許可のある体験（仮写真つき）を表示する。

2026-10-20 に UI を刷新した（オーナー承認のモック「改善版」）。白基調のニュートラル、手描きのアイコンと手書きのアクセント、切手の縁と丸スタンプで「近所の人に会いに行く」温度を出す。

同日、オーナー承認のスマホ用モック v2（niho-app の `idea/mock/experience-site-refine-v2.html`）に見た目をできるだけ近づけた（オーナー判断 2026-10-20：「このモックの見た目にできるだけ本番実装を近づける。アセットもそのまま使ってよい」）。あわせて次を決めた。

- プレビューの表記は上部の黒い帯をやめ、フッター最下部の小さな1行に移す（プレビューだけ。pilot と合成で文言を分け、契約版を添える）。
- 写真の「Sample photo」タグと、カード・詳細の「Sample listing / Details to be confirmed」ピルは出さない。
- NIHO の自前の写真（`niho-*.jpg`）とホストの顔（`host-*.jpg`）を仮に使う（§6）。
- 詳細の「Your host(s)」の切手の写真は photos[1]（無ければ表紙）。

モックと意図して違えた点：カードの開催日・一覧の件数・予約の日程は実データ（ブラウザで読んだ availability）で示す。予約入力は既存の2画面（日時・人数 → 入力・確認）を保ち、日付と人数を自動で選ばない。

2026-10-21 に PC 版のデザインを足した（オーナー依頼「PC 版のデザインも対応して欲しい」。モック v3：<https://niho-experience-mock.pages.dev/>、v2 の 440px の枠を外したレスポンシブ版）。スマホの見た目は v2 のまま変えず、PC で組み替える（§2.3）。

## 1. 表現の考え方

- 主役は写真と人。地は白、区切りは淡いグレーの面（sand）と細い線。色は少なく、写真の色を邪魔しない。
- 英語のサイトの見出しはやわらかいセリフ体（Fraunces、weight 400 中心）、本文・操作は NIHOapp と同じ Nunito。**日本語の画面（`<html lang="ja">`：`/ja`・`/host`・`/write`・`/admin`）は、本文も見出しも NIHO アプリと同じ「NIHO Sans」にする**（#615。§2.2）。手書きの Caveat は短いアクセントだけに使う。
- NIHO のブランド緑（leaf）は主ボタンの地と下線に、深い苔色（moss）はリンク・focus・手書きの文字に使う。全面を塗らない。
- 手描きのアイコン（`#sketch` フィルタで線を少し揺らす）、丸スタンプ（`#rubber` フィルタでかすれ）、切手の縁、アーチ形の切り抜きは装飾。意味は必ず隣の文字が持つ（`aria-hidden`）。
- Slowhop から採り入れたのは「大きな写真・余白・人の紹介・整理されたカード」という考え方だけ。写真、ロゴ、文章、配色、ページ構成は流用していない。

### 2.2 書体

| 役割 | 書体 | 使いどころ |
| --- | --- | --- |
| 見出し | Fraunces（`--font-display`、400。数字は 300） | h1〜h3、数字の節の大きな数字 |
| 本文・操作 | Nunito（`--font-sans`） | 本文、ボタン、フォーム、価格 |
| 手書き | Caveat（`--font-hand`、`.hand` / `.eyebrow`、moss） | 見出し上の一言（例 "five to choose from"）、行程の時刻（"6:00 PM"）、ホスト名、数字の単位、絵はがきの地名、ヒーローの "home" |

手書きは短いアクセントだけ。本文・操作・価格・法的な文言には使わない。旧来の柿色の eyebrow（大文字の小見出し）は手書きの一言に置き換えた。

**日本語の画面の書体（NIHO Sans、#615）**。`<html lang="ja">` の画面（`/ja`・`/host`・`/write`・`/admin`）は、NIHO アプリ（niho-app `docs/design/font-style-guide.md` §3.1）と同じ組み方にする。実装は `apps/web/src/app/globals.css` の `@font-face "NIHO Sans"` と `html[lang="ja"]` のトークン、照合は `apps/web/src/lib/niho-sans.test.ts` と e2e（`host-screens`・`write-ui`・`english-type`）。

| 役割 | 書体と太さ | Apple 端末での字 |
| --- | --- | --- |
| 本文・大見出し（h1・h2 は 400。強調の h1 は 500） | Nunito（英字）＋ NIHO Sans。`--font-sans` と `--font-display` は同じ | ヒラギノ丸ゴ ProN W4 |
| 小見出し（h3・カードの体験名・FAQ の問い）・ラベル（600–700） | 同上の `font-bold` | ヒラギノ角ゴシック W6 |
| ボタン・強いラベル（800） | 同上の `font-extrabold` | ヒラギノ角ゴシック W7 |
| 900 | 同上の `font-black` | ヒラギノ角ゴシック W8 |
| 手書きの中の日本語 | `--font-hand` の Caveat のあと `NIHO Hand JA`（丸ゴ W4 を Caveat の大きさに縮める、`size-adjust`） | ヒラギノ丸ゴ ProN W4 |

- 見出しの格は、書体ではなく太さと大きさで分ける。日本語の部品では見出しに `font-sans` を直書きしない（トークンが同じなので不要）。日本語の見出しの字間は 0、行間は 1.35（画面ごとの `leading-*` は勝つ）。
- 日本語の Web フォントは配信しない（#612 の Zen Maru Gothic は外した）。端末の書体を `local()` で名前で指すだけ。Windows / Android は 游ゴシック・メイリオ・Noto に落ち、丸ゴにはならない（NIHO アプリと同じ）。
- 手書きは英字の一言に使う。行程の時刻のように読み違えると困る情報は、日本語の画面では手書きにせず `font-bold` の moss にする。
- 日本語の画面の中で英語のサイトの見た目を見せる所（ホストの体験のプレビュー、英語の記事を書く欄の題と本文）は `lang="en"` を付け、英語の書体（@theme の値）に戻す。
- 例外はヘッダーの丸スタンプ「鎌倉」（判子の飾り、SVG のヒラギノ明朝）だけ。
- 単独のページ（ホストの招待・ログインのリンク、オフラインの画面）は `apps/web/src/lib/niho-sans.ts` の同じ定義をインラインで持つ。

文字：本文 16.5px / 行間 1.6。h1 はモバイル 34–42px、デスクトップ 52–78px。補足でも 12px 未満にしない。
角丸：カード・写真 22px、入力 12px、ボタン・チップは pill。影はカードと予約カードだけ。
余白：画面端 20px（モバイル。モック v2 に合わせた）/ 24px / 40px。セクション間 72px（モバイル）/ 104px（デスクトップ）。最大幅 1200px。

### 2.3 画面幅と組み替え

- スマホの組み方が基本。PC は Tailwind の `lg`（64rem = 1024px）から組み替える（モック v3 の 900px に当たる）。`sm`（40rem）〜`lg` 未満のタブレットは、余白と一部の列数だけ広げたスマホの組み方。
- 予約入力の2画面だけは、画面幅ではなく部品自身の幅（container query `@4xl` = 56rem）で2列にする。公開文書の枠の中など狭い所に置かれたときは1列のまま。
- PC の組み替え：ヘッダーに Host with NIHO、トップの検索は1行のピル、一覧の人数と日付チップは1行、詳細はパンくず → タイトル → ページ幅の中のモザイク → 本文と右の予約カード、予約入力は左に step・右に要約カードと追従する合計のカード、提供者入口の流れは4列（§4）。
- 実装の注意：presentation の CSS（`@niho/experience-presentation/v1/styles.css`）は全規則が `@scope (.nexp-v1)` で包まれていて、同じ詳細度なら scope の近さで Web 側の規則に勝つ。`.nexp-v1` の中に置く Web 側の部品（トップの検索欄など）で、presentation の CSS にもある基本クラス（`relative`・`grid-cols-2`・`rounded-2xl` など）を `lg:` で上書きすると、PC の指定が負ける（2026-10-21、トップの検索欄が PC でも2段のままだった）。画面幅で変える値は `max-lg:` と `lg:` に分けて書き、基本クラスを持たせない。

## 4. 画面

### トップ（`/`）

2026-10-29 にオーナー承認のモック A（<https://niho-experience-top-mock.pages.dev/a-journal-grid.html>）の構成に変えた（オーナー判断「体験が最優先。体験を先に出して、その下に記事も。記事は今後たくさん増えるので、サムネイル画像とセットで一覧できるように」）。presentation の `HomeViewModelV1.layout: "journal"` で組む。

上から：ヘッダー → ヒーロー（従来より低い 460px / PC 560px）→ テーマ → カード → 予約の流れ（カードの直下）→ 記事（Kamakura Journal）→ ホスト募集の帯 → フッター（プレビューだけ最下部に1行の表記）。

特集・動画の帯・ホスト紹介・数字・絵はがきは `layout` を渡さない従来の構成（日本語版トップ）にだけ残る。下の表のそれらの行は従来の構成の説明。

| 節 | 内容 |
| --- | --- |
| ヘッダー | 白。ロゴ、Experiences（一覧では淡い面で選択状態、`aria-current="page"`）、Host with NIHO（スマホは Experiences だけ）、"EN · ¥"（操作ではない表示。読み上げは "In English, prices in Japanese yen"） |

### 一覧（`/experiences`）

- 手書き "small groups · local hosts"、h1 "Experiences in Kamakura"、円・税込・JST の補足。
- ヘッダーの下に固定する絞り込み：上の行に人数のピル（Any group／1〜8）、下の行に Any day と今日から7日の日付チップ（曜日＋日、JST。トップから8日目以降の日付が来たらそのチップを足す）。チップの行の右端に小さな丸い検索ボタン（虫眼鏡）。PC は人数のピルと日付チップを1行に並べ、間を細い線で区切る。
- 検索（`q`。API 1.2 ではテーマも）は `<details>/<summary>` の中の GET フォームで、押すと入力欄がチップの下に開く。JS なしでも開閉・送信できる。`q`（やテーマ）が URL にあるときは開いた状態で語を表示する。0件や日程を読めないときは同じ検索を独立した行に出す。
- 日付・人数の絞り込みはブラウザから各体験の availability を1回ずつ読み、その日に予約可能で残席 ≥ 人数、かつ商品の1組の上限 ≥ 人数の開催回がある体験だけを出す（`lib/date-filter.ts`）。残席数そのものは表示しない。読込後はチップの下に件数、0件の日は無効。読込中は控えめな文言、失敗したら絞り込みを出さず全件と短い案内。
- URL の `date`・`guests` を読み、変更は `history.replaceState` で同期する。`date` 付きの URL は noindex（canonical は `/experiences`）。
- 0件と通信失敗はそれぞれ行動できる表示にする（検索を消す、Any day に戻す、人数を減らす、再試行）。

### 詳細（`/experiences/[slug]`）

- スマホ：先頭に横スワイプのギャラリー（"1 / N"、一覧へ戻る丸ボタン）。PC：パンくず → タイトル → 表紙＋4枚のモザイク（ページの幅の中・角丸）、"Show all N photos"（`<dialog>`。Esc・閉じるボタン、読み上げ見出し付き）。文書の順はタイトルが先で、スマホではギャラリーを見た目だけ先頭に出す。
- タイトル部：手書きの開催曜日と時刻、h1、レビューの 1 行（§3 レビュー。無い配備では出さない）、ホストの行（顔写真／頭文字の重なり＋"Hosted by …"＋提供者名）、手描きアイコン付きの事実（所要時間と時刻 JST、言語、人数と子どもの条件、集合を公開している場合は accessNote の要約）。
- 本文：リード、highlights（語でアイコンを選ぶ）、What you'll do（3段落目以降は畳む）、行程（写真付き、時刻は手書きの12時間表記、写真なしはアイコンのタイル）、ホスト（見出しは Your host(s)、ホストがいなければ Who runs it。切手の縁の写真＝photos[1] か表紙（オーナー判断 2026-10-20）、丸スタンプ、`provider.tagline` を手書きの引用、顔写真付きのホストのチップ）、含む／含まない（手描きの ✓ / ×）、集合場所、Good to know（参加の条件の行 → 提供者の一覧 3件＋"Show all N"）、Not suitable for、"Ask {host} a question"、Reviews（§3）、取消（全商品共通の条件のときだけ要約。補足は全商品が承認制なら "Your hosts confirm each request. You are only charged if they accept."、即時確定なら "Your booking is confirmed as soon as you pay."、混在なら "This policy applies to the option and date you select."）、販売者と Seller information。決済取消からの戻りは案内を出す。
- Good to know と質問（Epic #103・仮契約。`EXPERIENCE_API_MODE=mock` のときだけ出し、実 API の配備では出さない）：条件は種類ごとの行（§3 参加の条件）。質問のボタンは Good to know の下（Good to know が無い体験は、取消の前にボタンだけ）。予約を受けていない体験には出さない。条件が空の体験は従来の一覧だけで、崩れない。
- 集合場所：PUBLIC なら名前・住所・アクセス・入口の案内・"Open in Maps"（https のみ）と、`exteriorPhotoIndex` の写真をアーチ形で。AFTER_BOOKING は「予約確定後に案内」。
- 予約：PC は右の固定カード（"¥X / adult"、子ども料金、税込、開催曜日と時刻、ブラウザで読んだ次の開催日を最大3つ＝押すと `/book?date=&offer=` でその日を選んだ状態から、"Check dates and book"、取消の時間、承認制なら "Your hosts confirm each request — you're only charged if they accept"、"No account needed"、"Secure payment by Stripe"）。人数・合計は置かない（予約入力の役割）。スマホは下端の固定バー（価格＋次回日 or 曜日の要約＋"Check dates"。次回日は商品が1つなら "Next: Thu 22 Oct · 6:00 PM" と商品名を付けない）。予約停止中（`BOOKINGS_ENABLED=false` か `checkoutAvailable=false`）は停止の案内だけで、予約の入口を出さない。
- 題名（とレビューの 1 行）の下、ホストの行の前に、ブラウザで読んだ次の開催日（カードと同じ "Next" と日付のピル。予約を受けている体験だけ。残席は出さない。契約に日ごとの締切の時刻が無いので「あと何日で締切」は出さない）。ホストの節には、ホスト紹介文（`hosts[].bio`）があれば書式なしの文で出す（#146）。
- FAQ（#146・仮契約。mock のときだけ）：取消の前に "Frequently asked questions"（h2）と質問ごとの h3・答え。項目の間は細い線。無い体験は節ごと出さない。
- 本文の後（ページの幅）：その体験を扱うガイド記事への枠 "Guides for your visit"（記事が無ければ出さない・#145）と、"More experiences in Kamakura"（ほかの体験 2〜3 件をカードで。同じテーマを先に。一覧が読めなければ出さない）。英語版だけ。
- NIHO の公開 DTO から表示する。正規 URL は API の `canonicalUrl`。プレビューの fixture は構造化データとして出さない。

### 予約入力（`/experiences/[slug]/book`）

- 見た目はモック v2（pBook）。2画面の流れ（SlotPicker → Continue → BookingForm）はそのまま。戻るリンク "‹ 短い名前"、サマリーカード（公開文書が無いとき題名が h1）、手書きの step 1〜4（参加の条件に同意の対象がある体験は "Before you book" が step 3 に入り、"Your details" が 4、確認が 5）、下端の固定バー（§3）。公開文書（`booking` / `BookingPanel`）を使うときは文書の見出しがあるので題名は h1 にしない。
- PC（部品の幅が 56rem 以上）は2列：左に戻るリンクの下の step（商品の選択、step 1〜2／3〜4、案内、確認の行、注記、同意）、右の 380px にサマリーカード（スクロールで流れる）と、その下で追従する合計のカード（合計・日付と時刻・Continue／送信）。下端の固定バーは出さない。公開文書があるときと予約停止中は従来の幅（1列）。
- ブラウザから `getAvailability` を読み、商品・開催日・大人/子どもの人数を選ぶ。連絡先・回答は URL や Server Action へ送らない。詳細ページから来た `date`・`offer`（公開の日程だけ）は選択の初期値にする。
- 送信前に開催日（JST）、商品、料金内訳・税込総額、販売者、取消条件、同意文書と版を表示する。取消が無料の商品は、確認の行に "Free cancellation — Until Thu 12 Nov, 7:00 AM Japan time"（開催回の開始から契約の取消時間を引いた日時を、曜日・日付・Japan time で）を出す。その時間をすでに過ぎる日は "Not available for this date"。返金なしの商品には出さない。
- "Before you book"（Epic #103・仮契約）：同意の対象がある条件（`consentText`）を持つ体験だけ。枠の中に "Everyone in my group is OK with:" とその項目を並べ、チェックしないと進めない（チェック時は枠が緑の面になる）。利用規約への同意（"agree to version"）とは別の欄で、同意した条件の版を予約に添えて送る。送ったあとで条件が変わっていた（または、同意が要る条件が足されていた）ときは、赤い枠で「"Before you book" の点が変わった／確認する点がある」と知らせ、"Reload the experience" で詳細を読み直して新しい点を見せ、同意の欄を未チェックに戻す（名前・メール・質問の回答は残り、利用規約の同意はもう一度）。
- 入力は氏名・メール・任意の携帯電話（"Mobile number (optional, for the day)"。当日の連絡用で、提供者の当日の画面だけに出す＝owner 決定 2026-10-22。数字 7〜15 桁・mock のみ）・任意の備考と、商品に定義された申込時の質問だけ。国は収集しない。質問の見出しは "Questions from {host}"（ホスト名が長いときは従来の "Questions from your host"）。
- ブラウザから選別クライアントの `startCheckout` で NIHO へ直接送る。内容が同じ再送は同じ `clientRequestKey`、内容変更後は新しい key を使う。
- mock ではブラウザ内で合成 checkout を処理し、個人情報を伴わず `/preview/checkout` へ進む。この模擬ページは、決済後のページ（下）の 3 通りの見え方へのリンクを持つ。

### 決済からの復帰

- 決済後の確認画面と予約の状態は NIHO が所有する。サイトの `/booking/return` は、予約成立・決済済みを**断定しない**（戻り URL は何も証明しない）。「次に何が起きるか」だけを出す。
- 構成：手書きのひとこと（"almost there" / "thank you"）、h1、1〜2 文、"What happens next"（NIHO のメール → 前日の案内 → 当日 → レビューの依頼。手描きのアイコンを点線でつなぐ。状態の ✓ は付けない）、「この画面は予約の状態を見せない。NIHO のメールのリンクで見られる」の注記、"Didn't get the email?"（`/help`。メールの再案内の契約 niho-coliving/niho-app#19241 の後に接続）と "Browse experiences"。レビューの段は、レビューがある配備（今は mock）だけ。
- 見出しは戻り URL の `?type=instant|approval`（NIHO が足す固定の語。自由文は受けない）で分ける：instant＝"Check your email for your booking"、approval＝"The host will review your request"（"You are charged only if they accept"）、それ以外・無し＝"Check your email"。storage には何も残さない。NIHO の Stripe の戻り先は今は NIHO の状態ページで、この URL へは戻らない（`cancelUrl` だけ体験サイト）。戻り先はこの URL にする（owner 決定 2026-10-22。NIHO 側の実装は niho-coliving/niho-app#19331）。NIHO 側の変更が配備されるまでは、現在の状態ページへの復帰を維持する。

### 提供者入口（`/host`）

- 見た目はモック v2（pHost）：ヒーローの下にアーチ形の動画（`HOST_BAND_VIDEO`）、案内は leaf-pale の面＋家のアイコン、流れ4段は Caveat の数字と点線の区切りの行、"who does what" / "You host. We help." の YOU（sand）と NIHO（leaf-pale）の2つの面（✓）、料金と支払い（同じトーンの sand の面。数字は合意まで載せない）、最後に "See the experiences"（登録が開いているときは登録ボタンを主操作に残すため二次ボタン）。文言と登録の分岐は従来どおり。
- PC：ヒーローは文と動画の2列、案内の面はページの幅いっぱい、流れ4段は4列（Caveat の数字が上、列の間に点線）、YOU / NIHO は2列、最後のボタンは文字の幅。
- `HOST_SIGNUP_MODE=pilot`（既定）：少数の提供者から始めていると説明し、セルフ登録ボタンは出さない。`NIHO_HOST_START_URL` に正規の管理入口が設定されていれば、既存提供者向けの管理リンクを出す。認証・登録状況・口座の判定はNIHO側が行う。
- `open`：固定 URL で NIHO のログインへ。戻り先や商品を利用者が書き換えられるパラメータを付けない。Stripe の本人確認が必要な場合があると明記。
- `HOST_CONSOLE_ENABLED=true`：未ログインなら主操作を「NIHO でログイン」にする（`/host/auth/login`）。ログイン済みならホストの画面へ移る。引き継ぐ query は `providerId` だけ。

### ホストの画面（`/host/*`・[#84](https://github.com/niho-life/niho-experience/issues/84)）

2026-11-03 のオーナー決定（#369）では、提供者と体験の事前承認を廃止する。[ホスト自身による体験の公開](host-publication.md) を目標仕様とし、画面モックは自己公開へ変更する。以下の「NIHO 接続版」の申請・審査・保存時停止は移行前 HTTP API の実際の動作であり、#330 の編集・公開 SSR の切替まで維持する。

- 旅行者向けとは別の root layout。日本語（`lang="ja"`）、`noindex`、`private, no-store`、計測なし。旅行者の画面との間は全体を読み込み直す。

- 枠（`HostShell`）：PC（`md` 以上）は 232px の左サイドバー（ブランド・提供者の切替・ホーム／体験／カレンダー／予約／売上）。スマホも同じ5項目を下端タブ（アイコン＋12px のラベル）にし、「カレンダー」と省略せず表示する。設定、「記事を書く」「体験サイトを見る」「NIHO アプリ」、ログアウトはPC・スマホともアカウントメニューに置く。販売者表示・ホスト紹介・提供者のNIHOサポートは設定一覧へ集約し、提供者0件の通常Spot向けNIHOサポート入口だけはアカウントメニューと登録案内に残す。提供者切替と `?providerId=` の引継ぎ、0件・role・商品運営者の境界は変えない。選択中は sand の面と ink の文字で、緑は使わない。下位画面（体験の編集など）は「‹ 体験」の戻るヘッダーにして下端タブを出さない。本文は最大幅 1040px、ページ題（h1）は日本語の画面の大見出し（NIHO Sans の 400〜500、§2.2。以前は Fraunces から明朝に落ちていた）、面の小見出しは sans の太字。

### 管理画面（`/admin/*`・[#542](https://github.com/niho-life/niho-experience/issues/542)）

- **枠と部品はホストの画面と同じ**：`AdminShell` は `HostShell`／`HostNav` の作り（PC は 232px の左サイドバー、スマホは上の帯と下端タブ、下端のアカウントメニュー、白地）。ボタン・面・行・ダイアログ・結果の行（`HostNoticeLine`）・ピルもホストの部品をそのまま使い、独自の色・寸法を足さない。ブランドの横に小さな札「管理」を置く。基準モック: `idea/mock/admin-console-host-taste-v1.html`。
- **メニューは今のログインで使えるものだけ**：順番は 予約支援・予約・通知・提供者・運営者・掲載準備・掲載先（`lib/admin/sections.ts`。出し分けは `sections-server.ts` の 1 か所で、layout と各ページが同じ関数を使う）。Google ログインでは 予約支援・通知 が出ない。使えないページを直接開いたときは、メニューの先頭のページへ移す。サインインが成立していない間（更新中・失効・確認失敗）はメニューを出さない。
- **スマホのタブは 5 つまで**：メニューの先頭から 5 つ。6 つ目以降はアカウントメニューの中にリンクで並べる。通知の未読数はタブのアイコンの右上、PC は項目の右端に出す。
- **説明の段落を置かない**：見出しの下に案内文を足さない。結果は見出しの下の 1 行（`HostNoticeLine`）。
- **運営者（`/admin/operators`）**：体験ごとに 1 面（人がいない体験も出す）。面の頭に体験名と「＋ 招待」。体験の一覧に無い体験（アーカイブ済み・一覧の上限の外）でも、有効な担当か受諾されていない招待があれば面を出し、解除・取り消しができるようにする（その面に「招待」は出さない）。行は有効な担当、受諾されていない招待の順で、受諾済み・失効・解除済みは出さない。担当は「解除」、招待は「取り消す」（確認のダイアログを通す）。招待は名前だけを入れ、リンクは作成直後のダイアログに 1 度だけ出す（閉じると再表示できない）。結果が分からないときは「結果を確認」で同じ `commandId` を送り直し、確かめ終わるまで他の操作は押せない。
- **予約（`/admin/site-bookings`・S3）**：「一覧 ＋ 開いた予約」の 2 列（`xl`＝1280px 以上。スマホ・幅の狭い画面は一覧 → 予約の 1 画面ずつで、予約の上に「‹ 一覧」）。一覧の上の切替は 要対応（既定。承認待ち・取消の依頼・確認待ちの支払い・返金）／すべて／通知／精算。選んでいなくても PC は先頭の予約を右に開く。お金の操作（取り消して返金する・お断り・返金のやり直し ほか）は開いた予約の操作の帯にだけあり、確認は `ModalDialog` の中で「最新の状態と金額を確認 → 実行」の 2 段（承認待ちの辞退は `HostConfirmDialog`）。案件・報酬の振込・決済費用は開いた予約の中の畳む面。予約番号の入口は見出しの右の検索の 1 つ。操作ロック中（結果の確認を含む）は、ほかの予約・切替を選べない。
- **提供者（`/admin/products`・S2）**：一覧（行全体が 1 件のページへのリンク。ピルは例外だけ＝「公開名なし」「販売者なし」）→ 1 件のページ（公開情報・写真・体験）。登録（「＋ 登録」）と写真（「＋ 写真」）はダイアログで行い、承諾の checkbox の文言は変えない。スマホで 1 件のページを開いている間は、上の帯が「‹ 提供者」になり下端タブを出さない（`adminBackLink`）。

## 7. アクセシビリティ

- 360px・320px で横スクロールなし、主操作が画面内（E2E で検証）。PC の組み替え（検索の1行・詳細の順・予約の2列・一覧の1行・提供者の4列）はデスクトップ（1280px）の E2E で検証する。横スクロールの列（カード・動画・絵はがき・ギャラリー・日付チップ）は列の中だけで動く。
- キーボード：Skip link、全操作に focus 表示（moss の 3px 枠）。スクロールする列は focus できる。写真の一覧は `<dialog>` で Esc で閉じる。
- 状態は色だけでなくアイコンと文言で伝える。エラーは `role="alert"` と focus 移動。
- 画像はすべて代替文。装飾（手描きアイコン、スタンプ、動画、モザイク、顔）は `aria-hidden` か空の代替文で、意味は隣の文字が持つ。言語の略記（"EN · JA"）は読み上げ用に元の表記を持つ。
- 動きは最小限で、`prefers-reduced-motion` で止める（動画は再生しない）。
- axe（WCAG 2.2 AA）で重大な違反なし（E2E で検証）。

## 8. 文言の約束

- 英語は短く、具体的に、次に何が起こるかを書く。CTA は結果を表す動詞（Check dates and book、Find experiences、Continue to secure payment）。
- 価格は「¥6,800 / adult」（商品で違えば「From」）。子ども料金があれば別に示す。総額には「Japanese yen, tax included」。時刻は「6:00 PM – 8:30 PM JST」、日付は「Sat 24 Oct」。
- 開催曜日は契約上「表示の要約用」。実際の日付はブラウザで読んだ availability だけで示す。
- 人気、残席わずか、販売実績は実データがあるまで表示しない。レビューは、予約者だけが書き、投稿されたらそのまま公開されたものだけ（owner 決定 2026-10-22。NIHO は公開前に確認しない：owner 決定 2026-10-31）。平均とスターは 3 件から。プレビューの合成のレビューは名前に "(sample)" を付け、構造化データには出さない。プレビュー（合成例・pilot）であることはフッター最下部の1行で示す。
- 現在の英語文言・提供者の人物像は合成例か推奨値。実商品の原稿は担当3（#13）が事実確認したものに差し替える。

## 9. ホストの商品・質問編集

- NIHO 接続版の体験編集では、本文の下に最大 50 件の商品を表示し、追加・表示順の移動・外すを行う。追加した商品は受付停止で始める。外す操作は未保存の変更で、予約履歴がある商品の削除は API が拒否したあと受付停止を案内する。
- 商品ごとに予約時の質問を最大 5 件設定する。短文・長文・1つ選択・複数選択を選べる。選択式は 2〜8 個の選択肢を追加・削除・並べ替えできる。商品・質問・選択肢の新しい ID は API が発行する。
