# 街の人（日本語サイト、#564）

日本語サイトの `/ja/people`（一覧）と `/ja/people/<slug>`（人ごとのページ）。親は #561。英語サイトの表示・URL は変えない。

## だれが載るか（提供者 × メンバー、#589）

- **載るのは人**。提供者（事業者）はコンテンツの持ち主の単位で、それ自体ではログインしない。個人のアカウント（ホストアカウント）がメンバー（OWNER・共同ホスト・商品だけの運営者）として属し、個人でログインすると、属する提供者の管理画面に入る。街の人の掲載は「提供者 × メンバー（ホストアカウント）」に付く。人物ページは人と所属（例：高浜拓也・NIHO kamakura）。同じ提供者に何人でも載せられる。
- **事務局が決める**。Admin の「街の人」（`/admin/people`）、運営 CLI の `people apply`。運営を手伝う人（#528）は、載せないかぎり載らない。
- 掲載（`experience_people_listings`、migration `0077`、`0083` で作り直し）は、掲載の id（`plg_…`）・提供者（`provider_id`、メッセージの届き先）・メンバー（`member_id` ＝ `provider_memberships.niho_user_id` のホストアカウント。まだアカウントが無い人は空＝下書き）を持つ。**名前（40字）・写真・肩書（80字）・エリア（40字）・本人のひとこと（任意、160字）・紹介文（任意、1200字）・並び順・スラッグ**・「この人に会える体験」は掲載ごとに持つ。提供者の公開プロフィール・提供者の紹介文は読まない（提供者は事業者のことがある）。
- 写真は掲載が `photo_asset_id`（提供者のメディアの資産。どの提供者のものでもよい）・代替テキスト・クレジットで指す。新しい掲載で写真を書かなければ、提供者自身の `PROVIDER_PHOTO` を取る。許可の条件は今まで通り（`READY` で `rights_confirmed_at` がある）。
- 「紹介のみ／相談で受ける／予約できる」は見出しの札にしない。体験があれば体験の一覧が出て、無ければ出ない。どの人にも「◯◯さんにメッセージを送る」（本人あてのメッセージ。下の「本人にメッセージを送る」）が出る。

## 消えるとき

公開の読み取りは、次を**毎回**確かめる。どれかが欠けると、一覧・人ごとのページ・写真から消える（Admin が何も操作しなくてよい）。

- 掲載の行がある（外すと行を消す。届いたメッセージは提供者の受信箱に残り、宛先の名前も残る）。
- **メンバーが、その提供者の現役の OWNER か共同ホストである**（`provider_memberships` の `role IN ('OWNER','COHOST') AND active` で、`niho_user_id = member_id`、#589）。メンバーでなくなる（`active=false`）・EDITOR 等に変わると、一覧・人のページ（404）・体験の詳細の「案内する人」・一覧カードの「◯◯さんが案内」から消える。条件は `people-listings.ts` の `PEOPLE_MEMBER_CONDITION` の1か所で、公開の読み取りも本人へのメッセージの受付も同じものを使う。メンバーの無い掲載（下書き）は出ない（本人のアカウントが付けば出る）。
- 掲載の写真が、`READY` で許可の確認がある。許可を取り下げる（`REVOKED`）と、人ごとのページも一覧も写真の配信（`/api/public/experience-provider-media/<id>`）も止まる。

写真の配信は、これまで「公開中の体験がある提供者」だけだった。**掲載が指す写真**も配るように広げた（`getPublicProviderMediaAsset`）。それ以外の写真（事業者ロゴなど）の条件は変えていない。

## 人ごとのページの体験

その人の公開中の体験のうち、日本語の原稿があり、販売条件がある（予約できる）ものを、新しい順に並べる。いまは専用の小さなカード（写真・題・時間・料金）を使う。体験のカードを #529 が作り替えたら、そちらに差し替える。

## 体験のページ・カードからこの人のページへ

`PeopleListingRepository.personForExperiences(experienceSlugs)` が、体験の slug から、その体験を提供している登録済みの人（スラッグ・名前）を返す（写真があって表示される人だけ）。体験のページ・カードに「この人のページへ」を足すときに使う（このPRでは体験のページ・カードには触らない）。

## Admin

`/admin/people`（メニュー「街の人」。Admin のログインと、公開機能の flag が前提）。`GET/PUT/DELETE /admin/api/people`。一覧は、掲載（表示中かどうか）と、**まだ載せていない現役の OWNER・共同ホスト**（載せられる人）。`PUT` は `{listingId|null, providerId, memberId|null, expectedVersion|null, listing}`（`listingId` と `expectedVersion` は新規なら null、変更なら両方。別の提供者・メンバーへ付け替えられる）、`DELETE` は `{listingId, expectedVersion}`。メンバーは、その提供者の現役の OWNER か共同ホストでなければ 400。スラッグ・提供者のメンバーが重なる・版が古いときは 409。メンバーのいない掲載・メンバーでなくなった掲載・写真の無い掲載は「登録済みだが表示されていません」と出て、理由が下に出る。運営 CLI の `people list` も、登録済みで表示されない人に `hiddenBecause`（「本人のアカウントが提供者のメンバー（オーナー・共同ホスト）でないため非公開」「公開してよい写真が無いため非公開」）を付ける。

## 本人にメッセージを送る（#589）

人のページの「◯◯さんにメッセージを送る」は、団体・個別の相談（`/ja/inquiry`、事務局の一覧）ではなく、**本人あてのメッセージ**を作る。Airbnb のホストへのメッセージと同じ見せ方で、画面に仲介の説明（「事務局が見ます」「NIHO から返信します」）は書かない（オーナーの明示の判断、2026-11-13）。

- 入力は名前・メールアドレス（補足は「返信はこのアドレスに届きます」）・本文だけ。送ったあとは「◯◯さんに送りました」。
- 持ち方・通知・返信・保持期間・翻訳は、予約前の質問と同じ表と仕組み（[guest-questions.md](guest-questions.md) の「人物ページから本人へ」）。提供者の OWNER・共同ホストは `/host/messages` に「◯◯さんあて」として届いたものを読み、返す。
- 学校・法人・グループの窓口（`/ja/inquiry`・`/ja/business`・`/ja/schools`）は今のまま事務局が受ける。変えたのは人物からの入口だけ。古い `?from=provider&host=` のリンクは、文脈なしで相談のページが開く。
- 本人のアカウントが提供者のメンバーになっていない人（招待前）は、街の人に出ない。招待は本人への連絡なので、オーナーが行う。
- 届き先は**提供者の受信箱**で、「◯◯さんあて」と付く（掲載の名前をスレッドに残す）。OWNER と共同ホストが読み、返せる。返事のメールと返信ページの差出人は、宛先の人の名前。

## まだ無いもの

- hreflang への `/ja/people/*` の追加（英語に対応するページが無いため作らない）。sitemap には、街の人が1人以上のとき `/ja/people` と各人のページを載せる（[seo.md](seo.md)）。
- 人の紹介文を英語にすること（英語サイトに街の人のページは無い）。
- 体験のページ・カードからのリンク（上の `personForExperiences` を #529・#530 側で使う）。

## 会える体験との結び付け（#585）

載せたい人は、事業者の商品を案内している個人であることが多い（例：ZEN KARATE の商品を案内する指導者、NIHO kamakura のコミュニティディナーのマネージャー）。そこで、掲載に「この人に会える体験」を結び付ける（`experience_people_listing_experiences`、migration `0080`。`0083` で掲載の id に付け替えた）。

- **持ち方**：掲載ごとに、どの提供者のものでもよい商品を並びつきで持つ（**書いたものだけ**。提供者の商品が自動で付くことはない。`0083` は、これまで自動で出ていた提供者自身の商品を、既存の掲載に結び付けて移した）。掲載を外すと結び付けも消える。商品を置き換えるのは事務局だけ（管理画面の「街の人」の編集の「この人に会える体験」、運営 CLI の `people apply` の `listing.experiences`。[operator-cli.md](operator-cli.md)）。書いたときだけ全体を置き換え、書かなければ触らない。
- **人のページ**：その人の体験＝結び付けた公開商品（公開中のものだけ。停止・運営停止・下書き・未公開は出ない。公開の読み出しと同じ `visible_publications`）。日本語の原稿がある商品に絞って出す。
- **体験の詳細の「案内する人」**：その商品に結び付いた人（複数可。街の人の並び順）を、写真・名前・肩書とエリア・ひとこと・紹介・人のページへのリンクで出す。1人は「会いにいく人」、複数は「案内する人」。結び付いた人がいなければ、提供者自身の紹介。
- **一覧のカード**：結び付いた人がいれば「◯◯さんが案内」（複数は「◯◯・◯◯が案内」、3人まで）。いなければ、これまでの提供者名の行。
- 街の人は日本語サイトだけで、英語側には何も出ない。予約者・販売者・精算は変わらない（案内する人の表示と、販売者は別のもの）。
