# 街の人（日本語サイト、#564）

> **いまは止めている（#612、オーナー判断 2026-11-14）**：載せられる人が少ないので、`/ja/people` と `/ja/people/<slug>` は flag `EXPERIENCE_PEOPLE_PAGES_ENABLED`（`PEOPLE_PAGES_ENABLED`、既定 `false`）が `true` のときだけ出る。off の間は、この2つのページは 404（sitemap にも出さない）、トップの街の人の節・ナビ・フッターのリンク・体験の詳細の人物ページへのリンクは出ず、人物ページからのメッセージの公開 route（`/api/public/people/<slug>/messages`）も 404。**データ・Admin 画面・運営 CLI・提供者の受信箱は残り**、flag を `true` に戻せば元どおり出る。体験の詳細の「案内する人」と一覧カードの「◯◯さんが案内」は、名前と顔をこれまでどおり出す（人物ページへのリンクだけ外す）。以下は、flag が on のときの仕様。

日本語サイトの `/ja/people`（一覧）と `/ja/people/<slug>`（人ごとのページ）。親は #561。街の人ページは日本語だけ。体験詳細のホスト欄は英日で同じ構成にし、確認済みの英語プロフィールも表示する（#680）。プロフィールと公開・代理入力の詳細は[メンバーの紹介](member-profiles.md)を参照。

## だれが載るか（提供者 × メンバー、#589）

- **載るのは人**。提供者（事業者）はコンテンツの持ち主の単位で、それ自体ではログインしない。個人のアカウント（ホストアカウント）が提供者の現役 OWNER または共同ホストとして属し、個人でログインすると、属する提供者の管理画面に入る。街の人の掲載は「提供者 × メンバー（ホストアカウント）」に付く。人物ページは人と所属（例：高浜拓也・NIHO kamakura）。同じ提供者に何人でも載せられる。
- **事務局が決める**。Admin の「街の人」（`/admin/people`）で人を選び、掲載の有無・スラッグ・並び順を管理する。運営 CLI の `people apply` は既存掲載のスラッグと並び順を変更する。運営を手伝う人（#528）は、載せないかぎり載らない。
- 掲載（`experience_people_listings`）は掲載ID・提供者・メンバー・スラッグ・並び順を持つ。メンバーの名前・写真・肩書・エリア・ひとこと・紹介文は、`(provider_id, member_id)` ごとの本人プロフィールが正本。本人は `/host/account` から編集し、代理入力は本人の許可が有効な場合だけAdmin画面で行う。
- 初期プロフィール値は migration `0090_member_profiles.sql` で、本人が特定されている既存掲載からコピーする。メンバー未設定の掲載は旧内容を掲載行に保管し、あとで本人を割り当てたときプロフィールがまだ無ければ下書きへ移す。過去に表示されていたことや写真 asset の権利確認だけから、新しい本人公開同意・写真同意を推定しない。本人が確認して公開するまでは新しい公開版を作らない。
- メンバーは日本語の紹介を作り、肩書・エリア・ひとこと・紹介の英語案を確認して公開できる。公開には日本語の紹介文と権利確認済みの写真が必要。日本語は最大1,200字（200字くらいが目安）、英語は最大1,500字。名前は翻訳せず、英語を確認していないメンバーは英語体験ページに出さない。
- 写真はプロフィールが選び、本人の掲載同意と asset の `READY`・`rights_confirmed_at` の両方を要求する。本人の写真同意を撤回すると、人物ページ・一覧・体験詳細のプロフィール全体が非公開になる。
- 「紹介のみ／相談で受ける／予約できる」は見出しの札にしない。体験があれば体験の一覧が出て、無ければ出ない。どの人にも「◯◯さんにメッセージを送る」（本人あてのメッセージ。下の「本人にメッセージを送る」）が出る。

## 消えるとき

公開の読み取りは、次を**毎回**確かめる。どれかが欠けると、一覧・人ごとのページ・写真から消える（Admin が何も操作しなくてよい）。

- 掲載の行がある（外すと街の人からは消える。体験ごとのメンバー選択は独立しており、掲載を外しても変わらない。届いたメッセージは提供者の受信箱に残り、宛先の名前も残る）。
- **メンバーが、その提供者の現役の OWNER か COHOST である**（`provider_memberships` の `role IN ('OWNER','COHOST') AND active`）。メンバーでなくなる・EDITOR等に変わると、一覧・人物ページ・体験詳細から消える。
- 事務局の掲載行、プロフィールの公開版、本人の公開同意、写真同意、写真 asset の `READY`・権利確認がすべて有効である。どれかを失うと、公開読み取りから消える。

写真の配信は、これまで「公開中の体験がある提供者」だけだった。**掲載が指す写真**も配るように広げた（`getPublicProviderMediaAsset`）。それ以外の写真（事業者ロゴなど）の条件は変えていない。

## 人ごとのページの体験

その人の公開中の体験のうち、日本語の原稿があり、販売条件がある（予約できる）ものを、新しい順に並べる。いまは専用の小さなカード（写真・題・時間・料金）を使う。体験のカードを #529 が作り替えたら、そちらに差し替える。

## 体験のページ・カードからこの人のページへ

体験詳細は、公開中の選択をプロフィールの公開版と結合して読む。英語・日本語の表示は各公開版の言語で行う。カードの人物導線と街の人の公開 flag は既存どおり。

## Admin

`/admin/people`（Admin ログインと既存 flag が前提）は、掲載の有無・スラッグ・並び順を決める。本人が許可した場合に限って、同じ本人プロフィールの下書きを代理入力できる。Admin の下書き保存だけでは公開されない。本人がアカウントを使えない場合は、対象版の本人の口頭・書面の公開同意と Admin の確認を別々に記録して代理公開する。誰が最後に下書きを編集したかを記録する。Admin は体験へのメンバー紐づけを変更しない。

## 本人にメッセージを送る（#589）

人のページの「◯◯さんにメッセージを送る」は、団体・個別の相談（`/ja/inquiry`、事務局の一覧）ではなく、**本人あてのメッセージ**を作る。Airbnb のホストへのメッセージと同じ見せ方で、画面に仲介の説明（「事務局が見ます」「NIHO から返信します」）は書かない（オーナーの明示の判断、2026-11-13）。

- 入力は名前・メールアドレス（補足は「返信はこのアドレスに届きます」）・本文だけ。送ったあとは「◯◯さんに送りました」。
- 持ち方・通知・返信・保持期間・翻訳は、予約前の質問と同じ表と仕組み（[guest-questions.md](guest-questions.md) の「人物ページから本人へ」）。提供者の OWNER・共同ホストは `/host/messages` に「◯◯さんあて」として届いたものを読み、返す。
- 学校・法人・グループの窓口（`/ja/inquiry`・`/ja/business`・`/ja/schools`）は今のまま事務局が受ける。変えたのは人物からの入口だけ。古い `?from=provider&host=` のリンクは、文脈なしで相談のページが開く。
- 本人のアカウントが提供者のメンバーになっていない人（招待前）は、街の人に出ない。招待は本人への連絡なので、オーナーが行う。
- 届き先は**提供者の受信箱**で、「◯◯さんあて」と付く（掲載の名前をスレッドに残す）。OWNER と共同ホストが読み、返せる。返事のメールと返信ページの差出人は、宛先の人の名前。

## まだ無いもの

- hreflang への `/ja/people/*` の追加（英語に対応するページが無いため作らない）。sitemap には、街の人が1人以上のとき `/ja/people` と各人のページを載せる（[seo.md](seo.md)）。
- 英語の街の人一覧・人物ページや hreflang（引き続き対象外）。

## 会える体験との結び付け（#585）

載せたい人は、事業者の商品を案内している個人であることが多い（例：ZEN KARATE の商品を案内する指導者、NIHO kamakura のコミュニティディナーのマネージャー）。体験ごとの選択は、Admin掲載とは分けて `experience_product_member_profiles` に持つ。

- **持ち方**：`experience_product_member_profiles` にメンバーと商品を並びつきで結ぶ。最大3人を選び、体験の編集画面で現役OWNERが選択する。migration `0090_member_profiles.sql` は本人がひも付いた既存の選択を引き継ぎ、4人以上の体験は旧掲載の表示順を基準に先頭3人を残す。Adminは新しい紐づけを編集しない。
- **人のページ**：その人の体験＝結び付けた公開商品（公開中のものだけ。停止・運営停止・下書き・未公開は出ない。公開の読み出しと同じ `visible_publications`）。日本語の原稿がある商品に絞って出す。
- **体験の詳細**：英日で共通のホスト欄にホストの名前・紹介と選ばれたメンバーを表示する。メンバーの名前・写真・肩書とエリア・ひとこと・紹介は各言語の公開版を使う。街の人の公開 flag が有効なら既存の人物ページへのリンクも出す。
- **一覧のカード**：結び付いた人がいれば「◯◯さんが案内」（複数は「◯◯・◯◯が案内」、3人まで）。いなければ、これまでの提供者名の行。
- 街の人の一覧・人物ページは日本語サイトだけ。体験詳細のホスト欄は、確認済みプロフィールを英語ページにも表示する。予約者・販売者・精算は変わらない（案内する人の表示と、販売者は別のもの）。
