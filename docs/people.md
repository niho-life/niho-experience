# 街の人（日本語サイト、#564）

日本語サイトの `/ja/people`（一覧）と `/ja/people/<slug>`（人ごとのページ）。親は #561。英語サイトの表示・URL は変えない。

## だれが載るか

- **事務局が決める**。Admin の「街の人」（`/admin/people`）で、提供者ごとに「街の人に載せる」「街の人から外す」を選ぶ。運営を手伝う人は、ここで選ばないかぎり載らない（#528）。
- 名簿をもう1つ作らない。名前・写真・（本人が書いた）紹介文は、提供者の公開プロフィール（`experience_provider_public_profiles`、写真は `experience_provider_media_selection` の `PROVIDER_PHOTO`、紹介文は `provider_host_bios`）をそのまま使う。体験を持たない人（紹介だけの人、相談で受ける人）も、公開プロフィールと写真があれば載せられる。
- 載せるときに足すのは、肩書（80字）・エリア（40字）・本人のひとこと（任意、160字）・紹介文（任意、1200字。空なら本人の紹介文）・並び順・スラッグ（URL の一部。英小文字・数字・ハイフン）。テーブルは `experience_people_listings`（migration `0077`）。
- 「紹介のみ／相談で受ける／予約できる」は見出しの札にしない。体験があれば体験の一覧が出て、無ければ出ない。どの人にも「◯◯さんに相談する」（相談フォームを、その人を選んだ状態で開く。#532）が出る。

## 消えるとき

公開の読み取りは、次を**毎回**確かめる。どれかが欠けると、一覧・人ごとのページ・写真から消える（Admin が何も操作しなくてよい）。

- 登録の行がある（外すと行を消す）。
- 公開プロフィールがある。
- 提供者写真が選ばれていて、`READY` で、許可の確認（`rights_confirmed_at`）がある。写真の許可を取り下げる（`REVOKED`）と、人ごとのページも一覧も写真の配信（`/api/public/experience-provider-media/<id>`）も止まる。

写真の配信は、これまで「公開中の体験がある提供者」だけだった。**登録済みの人の提供者写真**も配るように広げた（`getPublicProviderMediaAsset`）。それ以外の写真（事業者ロゴなど）の条件は変えていない。

## 人ごとのページの体験

その人の公開中の体験のうち、日本語の原稿があり、販売条件がある（予約できる）ものを、新しい順に並べる。いまは専用の小さなカード（写真・題・時間・料金）を使う。体験のカードを #529 が作り替えたら、そちらに差し替える。

## 体験のページ・カードからこの人のページへ

`PeopleListingRepository.personForExperiences(experienceSlugs)` が、体験の slug から、その体験を提供している登録済みの人（スラッグ・名前）を返す（写真があって表示される人だけ）。体験のページ・カードに「この人のページへ」を足すときに使う（このPRでは体験のページ・カードには触らない）。

## Admin

`/admin/people`（メニュー「街の人」。Admin のログインと、公開機能の flag が前提）。`GET/PUT/DELETE /admin/api/people`。変更は、見た版（`expectedVersion`）を付ける。スラッグが重なる・版が古いときは 409。写真が無い人は「登録済みだが表示されていません」と出る。

## まだ無いもの

- hreflang への `/ja/people/*` の追加（英語に対応するページが無いため作らない）。sitemap には、街の人が1人以上のとき `/ja/people` と各人のページを載せる（[seo.md](seo.md)）。
- 人の紹介文を英語にすること（英語サイトに街の人のページは無い）。
- 体験のページ・カードからのリンク（上の `personForExperiences` を #529・#530 側で使う）。
