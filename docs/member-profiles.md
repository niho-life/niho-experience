# メンバーの紹介（#680）

## 正本と役割

- ホスト（提供者）ごとの紹介は引き続き `provider_host_bios` が正本。日本語を原文にし、英語はホストが確認した場合だけ公開する。個人ホスト向けの説明と団体ホスト向けの説明を分ける。
- メンバーの紹介は、ホストとメンバーの組ごとに1つ持つ。本人の「あなたのアカウント」で編集する。紹介文は日本語 1,200 字まで（200 字くらいを目安として案内）、英語は 1,500 字まで。名前・肩書・エリア・ひとこと・写真もこのプロフィールの項目とする。名前は翻訳せず、肩書・エリア・ひとこと・紹介文を翻訳案の対象にする。
- `experience_provider_member_profiles` は下書きの正本、`experience_provider_member_profile_publications` は現在公開中の版、`experience_provider_member_proxy_permissions` は本人が許可した代理入力の状態を持つ。1プロフィールは `(provider_id, member_id)` で識別する。
- `experience_people_listings` は事務局が街の人に載せる人を選び、スラッグと掲載順を管理するための掲載行とする。プロフィールの本文・写真の正本にはしない。掲載行が無ければ街の人には出さないが、体験のホスト欄はオーナーが選択できる。
- `experience_product_member_profiles` は体験とメンバーの公開プロフィールの選択を表す。選択はホストの体験編集画面から行い、体験ごとに最大 3 人。Admin は新しい紐づけを編集しない。旧 `experience_people_listing_experiences` から本人がひも付いた選択を migration で移す。メンバー未設定の掲載は人を識別できないため選択として移さない。
- NIHO の本人プロフィールを取り込まない。プロフィールや公開同意を外部の NIHO API に追加しない。

## 本人の編集・公開

- 現役の `OWNER` または `COHOST` だけが、自分の `(provider_id, member_id)` のプロフィールを読んで編集できる。HTTP の認証は `/host` の現在の本人を解決し、Store でも membership を再確認する。
- 編集内容（下書き）と公開内容は区別する。本文や写真の変更を保存しただけでは、公開中の版を書き換えない。日本語の紹介文と権利確認済み写真を含む下書きだけ公開できる。本人の公開操作で、日本語の公開同意・写真の掲載同意を記録して新しい公開版にする。英語は日本語原文の fingerprint が一致し、本人が確認したものだけを公開版に含める。
- 写真同意を撤回したら、そのメンバーの公開版を体験ページ・街の人ページの両方から直ちに外す。プロフィール公開の読み取りは毎回、現役の OWNER/COHOST membership・プロフィールの公開状態・写真同意・写真 asset の `READY` と権利確認を照合する。街の人ページだけは事務局の掲載行も要求する。
- だれが最後にプロフィール下書きを書いたかを、本人のアカウントまたは Admin actor と時刻で記録する。

## Admin の代理入力と公開

- Admin の街の人画面は、掲載の有無・スラッグ・掲載順を管理する。プロフィール本文と写真は本人プロフィールから読む。
- 本人が許可した場合、Admin は同じプロフィールの下書きを代理入力できる。代理入力の許可は、本人がアカウントで与えた場合と、本人の口頭・書面の許可をAdminが確認して記録した場合を区別し、許可中だけ書き込みを認める。許可を撤回すると以後のAdmin書き込みを拒む。
- Admin の下書き保存は公開しない。本人が使えない場合の代理公開は、対象のプロフィール版に対する本人の口頭・書面の公開同意と、Admin の確認を別々に記録したときだけ行う。代理入力の許可だけでは公開できない。公開版に同意の方法・時刻・同意を記録した人・確認した Admin ID を残し、本人の連絡先や証拠文書は保存しない。
- 本人がアカウントで公開・撤回できる。撤回や写真同意の取り下げは Admin 操作に依存せず公開読み取りへ反映する。

## 体験ページと街の人

- 日本語・英語の体験詳細は同じホスト欄の構成を使う。提供者名・提供者紹介の後に、オーナーが選んだ最大 3 人を表示する。名前はそのまま、その他の文言は各言語の公開版を使う。英語を確認していないメンバーは英語ページに出さない。
- `/ja/people` と `/ja/people/<slug>` は既存の公開 flag を維持する。掲載、現役 membership、本人の公開版、写真同意のいずれかを失った人は一覧・人物ページから出さない。体験詳細は掲載行ではなく、体験選択と同じ公開条件を使う。
- migration `0090_member_profiles.sql` は `0089_booking_sales_channel.sql` の後に追加する。本人が特定されている既存掲載は、本文・写真を該当する `(provider_id, member_id)` のプロフィール下書きへ移し、掲載行からは消す。本人が未設定の掲載は旧本文・写真を掲載行に保管し、公開しない。あとからメンバーを割り当てる際、プロフィールがまだ無ければ旧内容を下書きへ移す。旧体験リンクは本人がひも付いたものに限って新しい選択へ移し、体験ごとに旧掲載順の先頭3人を残す。旧リンク表は移行履歴として残し、以後の読み書きには使わない。過去のAdmin入力や写真権利だけから、新しい本人公開同意・写真同意・Admin代理入力許可を推定して記録しない。本人が確認・公開するまで公開版は作らない。
- 公開同意と写真同意は公開版の `draft_version` に結び付ける。代理公開では口頭・書面の方法、同意時刻、確認者、実行Adminと確認時刻を別々に残す。プロフィール本文と写真が同じ版として保存されるため、同意後に下書きを変えると代理公開前の同意記録は無効になる。

## API 境界

プロフィールと体験ごとの選択は、このリポジトリの Experience store と `/host/api`・`/admin/api` の内部BFFで完結する。NIHO の選別 Host API `experience-host-api` v1.0.0 は変更しない。公開REST/OpenAPI契約も変更せず、公開サイトの SSR 読取モデルにだけプロフィールを加える。

## #680 から分ける事項

設定の「掲載名」と登録フォームは、旧 NIHO provider API に依存し、現行 HTTP mode では保存できない。#680 では表示名の編集可否を偽らず、掲載名のExperience内編集は別Issue #682 とする。
