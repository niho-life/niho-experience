# ADR 0002：ガイド記事の原稿の置き場所

- 状態：提案（オーナー承認待ち）
- 日付：2026-10-26
- 関連：[#145 記事基盤](https://github.com/niho-life/niho-experience/issues/145)、[#147](https://github.com/niho-life/niho-experience/issues/147)〜[#151](https://github.com/niho-life/niho-experience/issues/151) 記事の柱

## 決めること

`/guides` の記事の原稿をどこに置くか。候補は (A) このリポの Markdown（公開済みだけ）と、(B) NIHO 共通基盤の CMS と API。

## 判断

**(A) このリポの Markdown を採る。** 下書きは git 管理しない非公開台帳に置き、プレビューでだけ読む。書式と手順は [ガイド記事の原稿と公開手順](../content/guides.md)。

| 観点 | (A) リポの Markdown | (B) NIHO の CMS |
| --- | --- | --- |
| 責務（[architecture.md](../architecture.md)） | 記事は NIHO が書く編集物で、提供者が持つ原稿・価格・在庫・権限に触れない。公開本文の SSR・SEO はこのリポの担当 | 提供者の体験原稿と同じ正本に入れると、ホストの権限・審査の型を記事に合わせて広げる必要がある |
| 公開までの速さ | PR を出せば固定 SHA の配備に乗る。API の契約・配備が要らない | 記事の型・API・審査画面を NIHO 側に作ってから |
| 編集の確認 | PR のレビューと単体テスト（必須項目・`[CONFIRM]`・仮写真の禁止）で止められる | CMS の承認の流れを新しく作る |
| 未公開原稿の扱い | リポは公開なので、下書きはリポの外（非公開台帳）。公開 = リポへ移す PR | CMS の非公開状態で持てる |
| 書く人 | 当面はオーナーと NIHO の数人。git に慣れていない人には書けない | 画面から書ける |

体験ページは提供者が持つ原稿なので NIHO の API から読む（変えない）。記事は NIHO 自身の編集物で、数も月に数本なので、仕組みを増やさずに出せる (A) を採る。

## 見直す条件

- 記事を書く人が NIHO の外（提供者・地域の書き手）に広がる、または月 10 本を超える。
- 日本語版（[#154](https://github.com/niho-life/niho-experience/issues/154)）で人手の翻訳の承認を、体験と同じ翻訳の正本で扱う必要が出る。

このとき (B) に移す。Markdown の書式は API の型に写しやすいよう、先頭の項目と本文の部品を少なく保つ。
