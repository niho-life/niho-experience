# 体験サイトのタスク評価

[#53](https://github.com/niho-life/niho-experience/issues/53) の実施手順。コード確認、自動テスト、関係者による操作確認、初めて使う人の観察を別々に記録する。この文書を追加しただけでは評価完了にしない。

## 対象と準備

旅行者、個人・小規模の提供者、NIHO運営の各役割で、日常の目的を代表する参加者を募る。人数と選定理由、未評価の役割を記録する。実施者が手順を教える前に、参加者が自分で進められるか観察する。

- 合成データを使う検証環境と、体験サイト・NIHO API/Webそれぞれの固定SHAを記録する。
- Stripeの検証環境と合成宛先を使う。実在の顧客への送信や実課金を伴う操作は、この評価手順に含めない。
- 公開Issueには参加者名、メール、予約内容、確認token、管理画面の私的URLを載せない。記録は匿名の参加者番号とタスク番号にする。
- 各タスクの期待値を、実際に配備したAPIの状態と商品条件で決める。未配備機能は「未評価・依存Issue」と記録する。

## 条件の組合せ

全項目を同じ人に課す必要はない。対象の役割と利用状況に合わせて分担し、未評価を残す。

- 320/360pxのスマートフォン、デスクトップ、文字拡大、キーボード。読み上げの評価は実施した端末と支援技術を記録する。
- 初回・再訪・未登録・認証切れ・OWNER・EDITOR。別提供者や権限外の予約が表示されない。
- 遅い通信・応答順の逆転・通信断後の再試行。入力途中の切替、再読込、離脱と復帰。
- 即時確定・承認待ち・期限切れ・満席・停止・決済中断。確認メール未着と、個別連絡の送信失敗。
- 計測拒否、DNT、計測先の遮断。予約情報や確認tokenを解析・URL・録画へ送らない。

## 記録と判定

各タスクは「支援なしで完了 / 支援して完了 / 未完了 / 未評価」で記録する。所要時間は環境と併記し、速さだけで合否を決めない。迷った箇所、誤操作、本人が想定した結果と実際の結果、復帰できたかを短く残す。

公開段階ごとのゲートを分ける。既存拠点の試験販売では旅行者 T1〜T5 と NIHO運営 O1〜O2 を確認する。提供者 P1〜P5 は外部提供者向け v1 の追加ゲートであり、連携Bの機能が使える環境で評価する。未配備の機能は未評価・依存Issueとして記録し、完了した扱いにしない。

誤課金、他人の情報表示、予約状態の誤認、主要操作が完了不能となる問題は公開前に解消し、修正後に該当タスクを再評価する。その他の問題も影響と優先度をつけ、既存Issueへ追記するか新規Issueにする。実施していない役割・機能を合格に含めない。
