# 鎌倉の体験をみんなで育てる事業方針

更新日：2026-10-24

NIHO Experienceは、鎌倉で育まれている豊かな暮らし・文化を海外の人にも分かち合い、その価値に見合う収入を担い手が得て、いい街を育てていくプロジェクトを目指す。NIHOの使命である「人と人の生きた繋がりを作って街を育てる」を、体験の提供・制作・紹介・通訳など、さまざまな参加の仕方に広げる。

**NIHOの役割は、いろいろな関わりしろのあるプロジェクトを作り、協力が続くエコシステムをデザインすること。** 「鎌倉の人たちがみんなで応援して育てたくなるサイト」と、その背後で人・仕事・収入がつながる仕組みを育てる。

この方向性を事業の軸とする。以下のヘルプ募集、報酬配分、販路拡大は具体化する構想であり、現在の実装や販売条件とは区別する。

## 街の人が得意なことで参加できる

| 役割 | 関わり方 | 生み出す価値 |
| --- | --- | --- |
| コンテンツメイカー | 体験を提供し、掲載内容を確認して運営する | 暮らし・文化・技術に触れる機会と、安心して参加できる体験 |
| リファラー・エバンジェリスト | 自分の所属するコミュニティや関係者に、相手に合う体験を紹介する | 人への信頼を通じた出会いと、街を応援する仲間 |
| プロデューサー | 内容の組み立て、写真、文章、見せ方、販売先などを考えて支援する | 提供者の魅力が伝わり、購入・参加につながる商品 |
| トランスレータ | 通訳を担い、必要に応じて翻訳や文化的背景の説明を支援する | 言葉を越えた対話と相互理解 |
| その他の協力者 | 撮影、デザイン、予約対応、会場提供、地域案内など、得意なことで参加する | 体験を成立させ、継続するための支え |
| NIHO | 参加の入口、協力者との出会い、合意・報酬・運営の仕組みを整える | さまざまな人が力を発揮し、協力を続けられる土壌 |

一人が複数の役割を担ってよい。店舗を持つ人、鎌倉に住む人、以前住んでいた人、海外から地元を応援する人など、それぞれの関係や技能を生かせる。役割名は事業上の参加の仕方を表し、そのままシステムの権限や契約上の責任を定めるものではない。

応援としての紹介も、報酬を得る専門的な仕事も参加の形として大切にする。制作・通訳・運営の仕事は、必要な時間と対価を明確にして依頼し、継続的な無償労働を前提にしない。

## 店舗のヘルプに協力者が提案できる

NIHOサポートは、地域の協力者も担える形を検討する。提供者が困りごとを出し、それに応えたい人が具体的な提案をできる入口を作る。

たとえば藍染体験の提供者が「この体験を海外の人にどう見せればよいか、手伝ってほしい」と募集する。そこに「写真を撮ります」「英語の紹介文を一緒に考えます」「友人の旅行会社に紹介できます」と提案が集まり、提供者が一緒に進める相手を選ぶ。

想定する流れは次のとおり。

1. **ヘルプを出す**：目的、困りごと、依頼したい範囲、予算または希望する報酬方式を示す。
2. **提案する**：協力者ができること、成果物、進め方、必要な期間、報酬案を伝える。
3. **合意する**：提供者と協力者が担当・対価・承認方法を決め、NIHOは必要に応じて調整を支援する。
4. **制作して公開する**：提供者が内容と素材を確認し、合意した販路に掲載する。
5. **実施して振り返る**：成果物や予約実績に応じて精算し、改善や次の協力につなげる。

報酬は、撮影一式などの固定額、通訳一回ごとの料金、一定期間の売上の数％、これらの組み合わせを候補とする。売上連動の場合は、対象商品・販路、計算の基礎、期間・上限、取消・返金時の扱い、支払時期まで合意する。写真等の利用範囲、掲載時のクレジット、修正・終了時の扱いも制作前にそろえる。

初期はNIHOが募集を取りまとめ、人をつなぎ、合意と実績を記録する運用から検証できる。繰り返し必要になる仕事を見極めてから、募集・応募・進行管理・精算の機能を段階的に検討する。売上の自動分配や全協力者の決済口座登録を、構想の開始条件にはしない。

## NIHOが育てる仕組み

NIHOは、協力者が仕事を進めやすく、提供者が安心して依頼できる環境を整える。

- **参加の入口**：小さな紹介から専門的な制作まで、関われる仕事と期待を分かりやすくする。
- **組み合わせ**：提供者の困りごとと協力者の技能・関心を結び付ける。
- **信頼**：掲載内容の確認、実績の扱い、約束、相談窓口を整える。伝統や人柄を誇張せず、当事者の意向を尊重する。
- **仕事と報酬**：誰が何を担い、誰にいくら残るかを見えるようにする。
- **共通の運営基盤**：予約、連絡、空き状況、精算の負担を減らし、体験に集中できるようにする。
- **学びの共有**：うまくいった紹介や見せ方を、当事者の同意のもとで他の体験にも生かす。

NIHO自身も制作や通訳手配を担える。協力者が増えたときには、その人たちが主体的に活動できるようにし、NIHOへの依頼集中で提供件数が頭打ちにならない運営を目指す。

## 収入が担い手と街を支える

価格は、提供者の開催負担、協力者の仕事、旅行者が受け取る価値を踏まえて決める。検証の一例は**一組あたり税込5万円**であり、全商品を同じ価格にする前提にはしない。

NIHOの取り分は、エコシステムの維持・改善に必要な収入から考える。**NIHOの運営分を10％程度にする案も候補**とし、提供者、協力者、NIHOそれぞれが継続できる収支を目指す。これまで議論した独立販売20％・サポート30％は、立ち上げ支援をNIHOが担う場合の検討案であり、この構想の固定条件にはしない。

商品・販路ごとに、少なくとも次を分けて見積もる。

- コンテンツメイカーに残る金額
- 制作・紹介・通訳などの協力者への報酬
- NIHOの運営分
- 決済手数料、OTAや旅行会社等の販売費用、その他の実費

「NIHOの10％に決済費用を含むか」「協力者への数％はどの金額を基礎にするか」「通訳費は商品価格に含むか」は、販売前に明示する。費用を二重に数えず、旅行者の支払総額と関係者への配分が一致する見積もりを作る。販路によって費用が変わるため、OTAの手数料に自社サイト向けの率をそのまま上乗せしない。

NIHO自身も地域に根ざした事業者として、適切な納税、地域での発注、担い手への報酬を通じて街に還元する。収益で道具や場を維持し、技術を伝え、次の担い手が参加できることを事業の成果として捉える。具体的な地域還元制度や資金配分は、継続できる収支を確かめながら検討する。

## 紹介したくなる体験と関係を育てる

紹介の出発点は「この人に、この体験を勧めたい」という気持ちにある。たとえば、米国の空手道場に通う鎌倉出身者が、来日する友人に地元の空手体験を紹介する。友人が楽しみ、その様子が担い手や紹介者にも伝わり、次の紹介や改善につながる。

この循環を生むために、次を用意する。

- 提供者の人柄、背景、大切にしていることが伝わる紹介
- どんな人に向く体験か、料金・人数・所要時間・言語がすぐ分かる案内
- 友人にそのまま送れる日英のリンクや紹介カード
- 地域の人や紹介する人が内容を理解できる小さな体験・交流の機会
- 参加者と提供者の同意に基づく感想や活動報告

紹介を義務にせず、関わる頻度や深さを本人が選べるようにする。紹介報酬を設ける場合は、対象・計測・開示・費用負担を別途決める。既存の[30日間の流入検証](pilot-30day-plan.md)では紹介報酬を使わない方針があるため、実施条件の変更はその計画で扱う。

## 旅行者のいる場所へ届ける

自社サイトは、街と担い手の魅力を理解し、安心して人に紹介し、予約できる場所として育てる。同時に、旅行者が既に利用している販売先や信頼する人との接点を増やす。

| 旅行者との接点 | 検討する動き | NIHOと協力者の役割 |
| --- | --- | --- |
| 出発前の旅行計画 | GetYourGuideなどのOTA、海外の日本旅行専門会社、国内DMCとの連携 | 掲載の制作支援、旅行会社向けの商品説明、条件と受入の調整 |
| 東京滞在中から鎌倉への訪問前 | 東京や鎌倉のゲストハウス・ホテル、ガイドからの紹介 | スタッフが勧めやすい案内、QR、最新の予約可能日への導線 |
| 趣味や地元のつながり | 海外の道場、文化のコミュニティ、鎌倉出身者や地域の知人 | 相手の関心に合う体験を個別に紹介できる材料 |
| 検索やAIによる旅行相談 | 英語の商品ページ、地域・文化を伝える記事、SEO・AIO | 正確で具体的な情報と、提供者自身の知識・写真を届ける |
| 購入意欲のある人への広告 | 検索広告などを小さな範囲で検証 | 販路ごとの利益と獲得費を見て継続判断 |

ゲストハウスは、地域の暮らしや文化に深く触れたい旅行者との接点として検討する。宿泊価格だけで客層を判断せず、同行者と一組5万円を払って参加したい体験かを確かめる。「今夜は東京、明後日は鎌倉」という需要には、提供者・会場・通訳が間に合う枠を案内できることが必要になる。

DMCや旅行会社には、関心の異なる顧客に提案できる少数の良質な体験と、受入条件・返信・当日の運営の確かさをセットで伝える。契約する業務範囲は、既存の体験提供の範囲と追加の手配業務を整理して決める。

SEO・AIOでは、英語の具体的な商品情報、文化の背景、料金・言語・開催条件を整える。GoogleはAI検索への掲載にも通常のSEOの基本が適用されると説明している。検索・AIで紹介されることを保証する施策として扱わず、実際の流入と予約で確かめる。[Google公式のAI検索向け案内](https://developers.google.com/search/docs/appearance/ai-features)

## 複数の販路でも運営しやすくする

提供者の承認のもとで、GetYourGuideなどへの掲載・改善を手伝うこともNIHOの支援に含めて検討する。予約が生まれる販路を増やすときには、掲載先ごとの契約、決済・返金、手数料、連絡方法に合わせて運用する。OTA経由の顧客との連絡や予約には、そのOTAのルールを適用する。

空き状況の管理は次の順で具体化する。

1. **少数の商品で運用を確認する**：日程管理の担当と確認元を一本化し、販路別の販売枠やリクエスト受付を使って重複販売を防ぐ。体験の枠に加え、会場・講師・通訳の確保まで確認する。
2. **既存サービスを比較する**：予約管理システムやチャネルマネージャーで、在庫、予約、取消、変更をどこまで連携できるか、費用と合わせて確認する。
3. **必要なAPI連携を設計する**：利用資格、連携範囲、対応する商品、同期失敗時の運用を確認してから開発する。カレンダー表示だけの連携で、予約時の枠確保まで保証されるとは扱わない。

GetYourGuideは予約管理システムとの接続を提供しており、対応システムにはBókunやRezdyなどがある。実際の対応範囲は接続先によって異なり、NIHOがそのまま直接APIを利用できることを意味しない。[接続の公式説明](https://supply.getyourguide.support/hc/en-us/articles/20309311919773-Connecting-Your-Product-to-a-Reservation-System-Inbound-Outbound-Connectors)・[対応システム](https://supply.getyourguide.support/hc/en-us/articles/14149999629853-Supported-Systems-Instructions)

現行の自社予約は、提供者を販売者とするStripe Connect DirectとNIHO共通基盤を前提としている。協力者への報酬や外部販路の精算は、支援の契約と合わせて別途設計する。価格・在庫・予約・売上の正本を公開サイト側に重複実装せず、責務の変更が必要な場合は[構成とデータ境界](../architecture.md)で扱う。

## 最初の体験と協力から確かめる

最初は核となる5つの体験を育て、販売と運営の準備が整ったものから試す。提供者の意向、文化への敬意、安全、価格、言語、受入条件をそろえ、旅行者が何を体験できるかを具体的に伝える。1〜2商品に制作と集客を集中することも選択肢とする。

各商品の立ち上げでは、最初の有料・実施済み30組程度を、販売・運営・協力者への依頼を学ぶ目安とする。提供者が自分で運営できるようになれば、必要な支援を減らしたり、別の協力者に頼んだりできる。件数だけで自立や手数料変更を自動判定せず、本人の希望と残る仕事に合わせて見直す。この件数の目安と、既存の30日間の流入検証は別のものとして扱う。

初期に具体化する仕事は、5商品の必要な支援を整理すること、最初のヘルプと協力提案を試すこと、紹介用の案内を用意すること、販路ごとの費用と受入体制を確かめること。募集機能や精算の自動化は、その運用から必要性を判断する。

成果は、次の観点を合わせて見る。

- **体験と収入**：実施済みの有料予約、提供者の手取り、協力者への報酬、NIHOに残る運営原資
- **関われる人**：成立した協力、繰り返し参加する人、提供者・協力者の負担と継続意向
- **紹介と信頼**：再び紹介してくれる人や提携先、参加者の感想、紹介先との関係の深まり
- **運営**：返信・承認にかかる時間、通訳の確保、取消理由、予約一件あたりの作業時間
- **街への還元**：地域で生まれた仕事、文化や場の維持・継承につながった具体例

計測は[予約ファネルと計測](funnel-measurement.md)に従い、確認できる予約・精算データを使う。OTA分は各管理画面との重複を確認する。個人名や私的な関係網を公開リポや計測URLへ載せず、追跡できない口コミを無理に特定の人へ帰属させない。

鎌倉で、参加する人が増えても質と収支が保てる形を見つけてから他地域への展開を検討する。その土地の人が自分たちの文化と関わり方を決められることを大切にする。
