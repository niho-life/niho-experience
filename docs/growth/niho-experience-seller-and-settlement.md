# NIHO体験運営：アカウント名義・メール・講師精算の初期設計

確認日：2026-10-29。位置付け：運用設計案。契約・税務の適用は実際の事業者、販売条件、課税方式に照らして確定する。口座や税区分の実情報は公開リポジトリへ保存しない。

関連：[カレンダー・外部サイト連携の詳細設計](../../idea/active/2026-10-29-ota-calendar-operations.md)、[12サービスの登録手順・①〜④の比較](ota-account-registration-and-operating-models.md)、[市場・販路調査](kamakura-experience-market-and-channels.md)。

## 1. まず採る構成

**NIHOが企画・販売・予約対応・返金窓口を担う体験は、NIHOを販売事業者とし、講師に実施を委託する。外部サイトはNIHOの事業者アカウントへ複数商品を登録する形を第一候補にする。** 講師はNIHO Experienceに自分のアカウントで入り、担当体験のカレンダーと予約だけを扱う。

これはアカウントを便宜的にNIHO名義へ寄せるだけの構成ではない。NIHOが販売条件、会場、実施者の手配、予約履行、問合せ・返金を実際に管理する商品に適用する。講師が独立して販売・催行する体験でNIHOが掲載作業だけを手伝う場合は、講師を販売事業者とする代行型にする。

オーナーは2026-10-29に「まず簡単な方法でよい。代理販売でNIHOが手数料を得る形も、NIHOが販売して実施委託する形も可。不要な税負担は避けたい」と回答。したがって会計処理を先に固定せず、**運営の実態、OTA契約、精算方法の三つを揃えて選ぶ**。税務判断は税理士へ具体的な契約と金額を示して確認する。

## 2. 二つの販売モデル

| 項目 | A：NIHO販売＋実施委託（初期推奨） | B：講師販売＋NIHO運営代行 |
| --- | --- | --- |
| 体験の販売事業者 | NIHOの実際の契約主体 | 講師の事業者 |
| 外部アカウント | NIHOに複数商品。各サイトの事業者審査に従う | 講師アカウント＋NIHOスタッフ／共同ホスト |
| 売上受取 | NIHOの事業用口座 | 原則講師。収納代行はOTA契約と実態が適合する場合のみ |
| 講師への支払 | 委託料・講師料として精算 | 講師の売上から合意したNIHO手数料等を精算 |
| 顧客対応・返金責任 | NIHOが販売者として担う | 講師が販売者。NIHOは委任された範囲で代行 |
| 初期登録の負担 | NIHOへ集約しやすい | 本人確認・口座等は講師ごとに必要になりやすい |
| レビュー・退出 | NIHO側の掲載に蓄積。独立時の移管を保証できない | 講師側の掲載に蓄積。NIHOの運営権限を解除する |
| 主な確認 | 講師委託が各OTAの実運営者要件に合うか、NIHOの消費税 | サブユーザー対応、収納・精算の権限、講師側の登録負担 |

「入金額の一部しか手元に残らないから手数料だけを売上にする」とは判断しない。逆に、NIHOの銀行口座へ入った金額がすべてNIHOの売上と決まるわけでもない。真の代理販売では受託者の手数料が役務の対価となる扱いがあり、契約と履行実態の確認が必要。[国税庁・消費税基本通達10-1-12](https://www.nta.go.jp/law/tsutatsu/kihon/shohi/10/01.htm)

商品・販売経路ごとにA/Bを記録し、予約成立時の販売者・精算条件をsnapshotで固定する。後から方式を変えても過去の予約を上書きしない。NIHO直販は[ADR 0002](../adr/0002-experience-domain-ownership.md)の販売者・Connect口座境界を守り、OTAで決済した予約をStripeで再課金しない。

## 4. 共通Gmailはどう使うか

結論は、**NIHOスタッフの予約窓口を共有し、講師には担当予約だけを通知する**。一つのログインをNIHOスタッフと全講師で共有する形は採らない。

| 用途 | 初期構成 |
| --- | --- |
| NIHOの予約・顧客連絡窓口 | 既存の業務メールを活用。複数スタッフで必要ならGmail委任またはGoogleグループを使う |
| OTAへログインするスタッフ | サイトの個人別staff招待／共同ホスト機能。各スタッフのメールで登録 |
| 講師の通知 | 個人メール＋NIHO Experience PWA通知。担当体験だけへ配信 |
| 講師本人名義のOTAが必要な場合 | 本人が所有・回復できるメールを使い、NIHOを正式な運営者として追加。新しい専用受信箱は必要な場合だけ |
| 本人確認・パスワード回復・入金通知 | 所有者と権限のあるNIHO担当者へ限定。全講師への転送対象にしない |

GetYourGuideはログインするユーザーのメールを個人ごとに求め、顧客連絡先の共有にはGoogleグループを案内している。**グループは連絡用アドレスであり、共通ログインIDではない。** [GetYourGuide公式](https://supply.getyourguide.support/hc/en-us/articles/13980973710493-Updating-the-Account-Management-Section-Managing-User-Access-and-Customizing-Notifications-in-the-Supplier-Portal)

Gmail委任はパスワードを配らずにメールを閲覧・送信・削除できるが、担当商品のラベルだけに限定する権限ではない。個人Gmailでは最大10代理人、Workspaceは管理設定・組織の制約があり、外部講師の個人Gmailへ同じように委任できる前提にしない。エイリアスは独立したGoogleアカウントではない。[Gmail委任](https://support.google.com/mail/answer/138350?hl=ja)、[Googleグループの共同トレイ](https://support.google.com/a/users/answer/9282734?hl=ja)

### 予約通知の渡し方

初期の手動運用では、NIHOスタッフが予約を担当講師へ必要最小限で連絡する。自動化では、通知メールまたはAPIをNIHOが取り込み、外部掲載ID→内部体験→現在の担当者を引いて配信する。件名に「水引」と含まれているだけで転送先を決めない。

自動転送を先に使う場合は、講師専用の受信先か確実な商品識別子で振り分けられるものに限定する。Gmailの転送先には確認手続がある。誤判定・複数商品・商品名変更に備え、識別できないメールはNIHOスタッフが処理する。[Gmail転送・フィルタ](https://support.google.com/mail/answer/10957?hl=ja)

通常の通知本文は「水引／11月の開催日時／1組2名／予約を確認」程度とし、詳細は認証後のPWAへ置く。決済情報、他商品の予約、認証コード、回復リンク、本人確認書類を自動転送しない。必要な参加者情報は担当体験の予約詳細で提供し、集客用名簿へ流用しない。

### アカウント作成の代行

NIHOは原稿、写真、英語、必要情報の整理、フォーム入力を支援できる。本人名義で求められる本人確認、代表権の申告、契約同意、口座情報は、その本人または正式な権限者が行う。専用メールをNIHOが用意しても、本人確認の主体がNIHOに置き換わるわけではない。

退任時は、NIHO側の担当・通知・委任を解除し、本人所有アカウントは本人へ回復手段を渡す。NIHO販売の商品は未催行予約の履行と代替講師をNIHOが引き継ぐ。既存レビューやアカウントを移管できるかは各社条件による。

## 5. 精算は月次明細から始める

初期はOTAごとの受取をNIHOに集約できる契約に限り集約し、催行済み・取消確定済みの予約を月次で講師ごとに精算する。入金予定と実際の銀行入金、催行日、講師への支払日は分けて残す。自動振込・自動申告は初期スコープへ含めない。

### 1件2万円の例

以下は手数料を合意したという意味ではなく、以前の「20%」を明確にする仮定。OTA費用を売価の20%、NIHO取り分をOTA控除後の20%、それ以外を講師への支払予定額とする。

| 項目 | 1件 | 月30件 |
| --- | ---: | ---: |
| 顧客支払総額 | 20,000円 | 600,000円 |
| OTA控除（仮定20%） | 4,000円 | 120,000円 |
| OTA控除後 | 16,000円 | 480,000円 |
| NIHOに残す額（上段の20%） | 3,200円 | 96,000円 |
| 講師への支払予定額 | 12,800円 | 384,000円 |

この96,000円は、税金・材料・会場原価・スタッフ・Claude等を引いた利益ではない。Aの販売モデルならNIHOの売上・OTA費用・講師費用を分ける。BならNIHO手数料と預り・精算を区別する。手数料率、税込／税別、材料負担、会場費の別徴収、値引き、キャンセル、源泉徴収を契約で明記する。「20%が税込か税別か」だけでも支払額が変わる。

### 保存する明細

- 予約ID、販売サイト、販売者、体験、講師、催行日、取消・返金状態。
- 売価、値引き負担者、通貨、換算根拠、OTA手数料・税区分、OTA受取予定・実績。
- 講師報酬の算定根拠、材料・会場の負担、税抜／消費税、インボイス確認結果と適用日。
- 源泉徴収の対象・税率・対象額・控除額、振込額、支払日、修正履歴。
- 適用した契約版。口座番号・個人番号は既存の非公開の経理手続で扱い、一般のカレンダーDBや通知へ保存しない。

## 6. 不要な税負担を避けるための確認

### 6.1 法人税は売上全額へそのまま課税されない

NIHOが法人で販売主体になる場合、法人税の基礎は益金から損金を引き、税務調整をした所得。売上を60万円計上することだけを理由に、60万円全体へ法人税がかかるとは考えない。適切なOTA費用・委託料等の記録が必要になる。[財務省・法人税の課税ベース](https://www.mof.go.jp/tax_policy/summary/corporation/c01.htm)

NIHOの主体が法人か個人か、すでにどの課税方式を採っているかを本調査では確認していない。ここで税額や最安モデルを断定しない。

### 6.2 差が出やすいのは消費税

NIHOが一般課税で、講師への支払が課税仕入れになる場合は、講師の適格請求書の有無等で仕入税額控除が変わる。簡易課税などを適用している場合は別の計算になるため、講師の登録有無だけで有利不利を決めない。[国税庁・仕入控除税額](https://www.nta.go.jp/taxes/shiraberu/taxanswer/shohi/6401.htm)

2026年度改正後の国税庁案内では、未登録事業者からの課税仕入れに係る経過措置は2026年10月から70%、2028年10月から50%、2030年10月から30%と段階的に変わる。古い「2026年10月から50%」という前提を使わない。適用条件、必要帳簿、上限、対象期間は経理で確認する。[国税庁・令和8年度改正](https://www.nta.go.jp/taxes/shiraberu/zeimokubetsu/shohi/keigenzeiritsu/invoice-review/index.htm)

単純比較の例：税込11,000円・税相当額1,000円の講師料について、全額控除できるケースと70%控除できるケースの差は300円。30回なら9,000円。この例は一般課税で経過措置の要件を満たす場合の**控除額の差だけ**で、NIHOの総納税額でも、代理販売へ変えれば必ず節約できる金額でもない。

本当に代理販売として整理できるならNIHOの役務対価を手数料とする構成は検討できる。しかしGetYourGuide等でNIHOが実運営者と申告する内容、顧客との契約、実際の責任と矛盾しないことが前提になる。名義の呼び方だけで総額／純額を切り替えない。

### 6.3 個人講師への源泉徴収

法人等から個人への技芸・知識等の教授指導料は、源泉徴収の対象になり得る。水引・書道・料理等の支払も「業務委託料という名前だから不要」とせず、役務内容と受取人を確認する。国税庁の説明では対象の報酬について通常100万円以下は10.21%。請求書で報酬と消費税が明確に分かれている場合の扱いもある。[国税庁・2026年源泉徴収のあらまし「報酬・料金」](https://www.nta.go.jp/publication/pamph/gensen/aramashi2026/pdf/07.pdf)、[No.2795](https://www.nta.go.jp/taxes/shiraberu/taxanswer/gensen/2795.htm)

源泉徴収をNIHOの利益・手数料に加算しない。対象の場合は「講師報酬総額」「源泉税」「振込額」を別表示し、NIHOが預かった税額の納付も管理する。これは通常、講師側の所得税の前払いであり、NIHOが得る追加収入ではない。材料費等の名目への付替えで回避しない。

### 税理士に渡す最小の確認事項

1. NIHOの契約主体・現在の消費税方式と、代表的な講師の事業形態・インボイス登録状況を基に、AとBの契約実態・会計・消費税を比較する。
2. 2万円の販売、OTA控除、講師報酬、材料・会場費の明細で、必要な証憑、税込／税別、海外OTA費用の税区分を確定する。
3. 個人講師への支払の源泉徴収、納付・支払調書等の要否、精算書の書式を確認する。

初期に税区分を確認して共通の精算様式を決める方が、後から全予約を組み直すより簡単。回答が出るまで税率を推測して自動精算・自動振込を始めない。カレンダー・担当権限・販路対応表の実装設計は独立して進められる。

## 7. 最初の運用セット

1. NIHO販売の体験を1つ選び、講師委託の内容と販売責任を1枚で合意する。
2. NIHOの業務連絡窓口を1つ決め、スタッフは個別ログイン、講師は担当通知のみとする。
3. 実際の2サイトで名義・商品・枠・通知・入金先を棚卸しする。
4. NIHO Experienceで担当講師を招待し、1組制のカレンダーと予約通知を使う。
5. 最初の月は実入金と予約を照合した明細を作り、人が確認して支払う。

この構成なら、講師ごとに全サイトのアカウント作成・Gmail共有・銀行設定を一括で求めずに始められる。講師名義が必要な例外だけ、正式な委任と本人手続を追加する。
